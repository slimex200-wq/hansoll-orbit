# HANSOLL ORBIT Architecture

## Architecture Decision

Use a modular monolith with explicit internal contracts.

- One Electron desktop application
- One shared domain model
- One local application store for the first deployment
- One Python bridge to the existing OpenCrab evidence engine
- Replaceable adapters for future company server, Microsoft Graph, SharePoint, and ERP access

This keeps the first deployment operable on the current Windows environment while preventing
search, task, document, and schedule modules from creating separate data silos.

## Runtime Components

```text
Electron renderer
  - Persistent Work Agent right sidebar
  - Search
  - Cases
  - Tasks
  - Artifacts
  - Timeline
  - Knowledge
  - Admin
          |
Secure preload API
          |
Electron main process
  - Command coordinator
  - AI provider selector and official-login launcher
  - Local domain store
  - Review gate
  - File-open service
  - Python process adapter
          |
OpenCrab Python engine
  - Audit and freshness
  - File/style/mail/fact/sketch retrieval
  - Business judgment and policy routing
  - Workbook validation
          |
Configured sources
  - Outlook export/index
  - OneDrive/Talbots source files
  - WIP, TP, BOM, costing, and templates
  - Future Graph, Teams, SharePoint, and AX adapters
```

Work Agent is mounted once at the application shell level rather than as a routed board.
Navigation therefore does not reset its draft query, in-progress request, answer, or saved-case
state. On wide desktop layouts it is docked beside the active board; below 1180px it becomes a
right overlay so operational tables keep their working width.

Model synthesis uses replaceable provider adapters. Personal ChatGPT/Codex and Claude Pro/Max
subscriptions run through each vendor's official CLI login. ORBIT persists only the selected
provider id and never copies provider credentials. Provider-specific answer caches prevent a
response generated by one model provider from being reused by another. Gemini personal OAuth is
not routed through ORBIT; a future Google connection must use an approved API key, Vertex AI, or
company gateway.

## Security Boundaries

- `nodeIntegration` is disabled.
- Renderer code uses a narrow `contextBridge` API.
- IPC channels are allowlisted.
- Python commands use argument arrays and never shell interpolation.
- File opening requires an absolute existing path.
- Controlled actions require a review token created from the current evidence snapshot.
- Microsoft credentials belong in Windows Credential Manager or the platform keychain; AI subscription credentials remain owned by each provider's official CLI and never enter the app store.
- Raw source files and raw mail bodies remain outside the repository.
- Local application data is stored under Electron `userData`.

## Evidence Reconciliation

Evidence is never silently overwritten.

1. Normalize exact business keys.
2. Group evidence by fact type and business key.
3. Rank by explicit user source, approved template/source workbook, WIP/allocation, recent mail,
   and supporting references.
4. Compare source dates and indexed dates.
5. Mark conflict when top-ranked sources disagree.
6. Require user review for material conflicts.
7. Preserve both the selected value and rejected evidence.

## Artifact Pipeline

```text
Find approved template
  -> Copy source workbook
  -> Build evidence table
  -> Apply no-source-no-fill
  -> Populate through a typed recipe
  -> Save output version
  -> Reopen and validate
  -> Request human review
  -> Mark share-ready
```

Each artifact family has its own recipe. Submit, dispatch, costing, recap, TNA, and internal
reports do not share a generic cell-filling implementation when their business rules differ.

## Deployment Evolution

The local store implements the same repository interface expected from a future company server.
Moving to multi-user deployment replaces the repository and connector adapters without changing
the renderer or domain commands.

Future shared deployment:

- API service with company authentication
- PostgreSQL for shared domain data
- Object metadata and search service
- Background connector and extraction workers
- Microsoft Graph, SharePoint, Teams, and AX adapters
- Central policy, template, update, and audit management
